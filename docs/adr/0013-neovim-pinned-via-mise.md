# 0013: Neovim pinned via mise on every platform

**Context:** `nvim/lazy-lock.json` is shared between machines through this repo, but the Neovim binary was not: each platform's package manager installed whatever version it had. When Homebrew moved one Mac to Neovim 0.12 while its plugins still sat on commits written for an older Neovim, nvim-treesitter and LazyVim's LSP setup broke on every start. A lockfile only works if the Neovim it was written against is the same everywhere. The same holds for the tree-sitter CLI that nvim-treesitter's `main` branch builds parsers with.

**Decision:** `neovim` and `tree-sitter-cli` come from the global mise config (`home/dot_config/mise/config.toml.tmpl`) on macOS, Linux and Windows, pinned to exact versions in its `$pinned` dict, and are dropped from the Brewfile and the winget manifest. Updating Neovim becomes a deliberate step: raise the pin, `chezmoi apply`, run `:Lazy update` (and `:TSUpdate`), check that nvim starts clean, then commit the new pin and `lazy-lock.json` together. No `mise.lock` on top: the exact versions already fix what gets installed, and aqua verifies each download against the project's published checksums.

**Consequences:** every machine runs the Neovim its `lazy-lock.json` was written against, so a lockfile synced from another machine no longer meets a different Neovim. Neovim no longer updates with `brew upgrade` or `winget upgrade`. nvim is on the PATH only where mise is active (the shells) or its shims are; git's `core.editor = nvim` works from a shell but not from a GUI git client. A machine provisioned earlier keeps its Homebrew/winget Neovim until it is uninstalled by hand; shells find mise's first, anything else may still find the old one.
