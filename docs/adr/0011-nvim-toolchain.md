# 0011: Neovim's toolchain is provisioned too

**Context:** ADR 0008 made the tools the deployed configs call into Applications, but stopped at the tools themselves. Neovim's LazyVim setup needs more on a fresh machine: `tree-sitter build` needs a C compiler, `telescope-fzf-native` and LuaSnip's jsregexp need `make` or `cmake`, the pickers need `ripgrep` and `fd`, Mason installs most servers and formatters through npm and pypi and unpacks the rest with `unzip`, and the icons need a Nerd Font. None of it was installed by the repo; it only worked where it had been installed by hand. mise was a Bootstrap Package with no configuration, so it installed nothing, and bash and PowerShell never activated it.

**Decision:**
- `ripgrep`, `fd`, `unzip`, `cmake` and `build-tools` (a C compiler plus `make`) join the CLI tools of every Profile. Platforms whose base system already provides one leave it out of their manifest: macOS ships unzip, and Homebrew's own install brings the Xcode Command Line Tools; Windows ships tar and Expand-Archive. On Windows `build-tools` means the Visual Studio Build Tools with the C++ workload, because the cc crate behind `tree-sitter build` expects MSVC there. `winget import` cannot pass the workload, so the Windows Application script installs it with `winget install --override` when vswhere finds no VC toolset. Windows gets no `make`: LazyVim prefers `make` over `cmake` when both exist, and `telescope-fzf-native`'s Makefile does not build with MSVC.
- node (LTS) and python come from a global mise config, `home/dot_config/mise/config.toml`, keeping ADR 0008's split: platform package managers for tools, mise for language runtimes. A `run_onchange_after_install-mise-tools` script per OS family runs `mise install` whenever the config changes. bash and the PowerShell profile now activate mise like zsh already did, so Neovim started from any shell sees those runtimes.
- `jetbrains-mono-nerd-font` is a GUI Application (not on dev-server): a Homebrew cask, a winget package, and on Linux, where apt has no Nerd Font, a chezmoi external that unpacks the Nerd Fonts release into `~/.local/share/fonts` (not in devpod).

**Consequences:** a fresh macOS, Debian/Ubuntu or Windows machine gets a Neovim that installs its parsers and Mason packages without manual steps. The Visual Studio Build Tools add several GB and a long first apply on Windows. apt names `fd-find`, whose binary is `fdfind`; LazyVim and Snacks look for both names. Fedora/Arch still get no Application manifest, and Debian/Ubuntu's `tree-sitter-cli` can be older than nvim-treesitter's `main` branch needs; both are left open. The CI asserts check the new manifest entries, the mise config and the Linux font, not the installs themselves.
