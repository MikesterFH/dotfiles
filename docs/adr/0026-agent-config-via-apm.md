# 0026: Agent harness config via APM

**Context:** Skills, instructions and MCP servers for the agent harnesses (Claude Code, GitHub Copilot, opencode) lived only on each machine, unversioned, and each harness had its own copy in its own format. MCP config is especially awkward: every harness uses its own schema and file, and Claude Code's `~/.claude.json` also holds app state, so chezmoi can't own it as a whole. A homegrown layer (one data file, a renderer per harness, a back-sync script) was weighed and rejected because of its ongoing maintenance cost. [APM](https://github.com/microsoft/apm) (Agent Package Manager) already translates skills, instructions, prompts, agents and MCP servers into each harness's format, merges MCP entries into the existing files, and removes what it no longer manages. A prototype against a scratch `$HOME` confirmed this, and also showed APM's limits; the consequences below come from it.

**Decision:**
- `apm` is an Application, a mise tool pinned to an exact version on every Profile (APM is 0.x and has moved deploy paths between minors). Windows ARM has no release build. Nix doesn't get it until nixpkgs packages it.
- chezmoi deploys only the global manifest `~/.apm/apm.yml` (`home/dot_apm/apm.yml.tmpl`), with targets `claude`, `copilot` and `opencode`. The repo is the only source for it (variant A): third-party packages, pinned to a tag or commit, and MCP servers are added there, never with `apm install -g <pkg>`.
- The dotfiles' own skills, instructions, prompts and agents are an APM package in `agents/` at the repo root. Like `keyboard/` (ADR 0025), chezmoi doesn't deploy it; APM does. The manifest references it by absolute path (`.chezmoi.workingTree`), because APM refuses relative local paths at user scope.
- `run_onchange_after_sync-apm-packages` (unix and windows) runs `apm install -g` and then `apm compile -g` (opencode's global `AGENTS.md`). Its trigger hashes the rendered manifest and every file in `agents/` (`.chezmoitemplates/apm-sync.json`). Before calling APM it unsets every `${VAR}` the manifest references: with the variable set, APM writes the secret's value into `~/.claude.json`; unset, the reference stays there.
- chezmoi manages nothing APM deploys (`~/.claude/{skills,rules,agents,commands}`, `~/.agents`, `~/.copilot`, `~/.config/opencode/{skills,agents,commands,AGENTS.md}`, the MCP entries).

**Consequences:**
- ADR 0001 now has an exception: like mise for CLI tools, APM is a second installer, run by a chezmoi script.
- `~/.apm/apm.lock.yaml` holds the absolute path and per-file deploy hashes of each machine, so it's local state and not committed. Reproducibility comes from the pins in the manifest. `mise.lock` pins APM itself.
- APM owns only what it deployed. Skills installed natively in a harness, plugins (`~/.claude/plugins`, opencode plugins) and Claude.ai-synced skills stay untouched. But two situations fail the whole install, and with it the apply: a native skill with the same name as a packaged one ("conflicts with unmanaged file"), and an APM-managed MCP entry changed in a harness (APM won't take it back, even with `--force`). In both cases APM prints the file or entry to remove, and the next apply retries. Local experiments use names no package uses (`agents/README.md`).
- There is no back-sync: a skill developed locally is moved into `agents/` by hand, and its native copy deleted.
- The CI asserts check the rendered manifest and the pinned mise entry, not what APM deploys, the same as every other script side effect.
- opencode gets no hooks at user scope; Copilot's commands are deployed as prompts.

**Update (Nix):** On a NixOS host the home-manager module (ADR 0021) takes `apm` from nixpkgs (`apm-cli`), which lags the mise pin (0.35.0 against 0.39.1; the drift report shows it). 0.35 covers what the manifest uses today: `install -g` for all three targets including MCP, and `compile -g`. A `home.activation` step copies the rendered manifest into `~/.apm/apm.yml`, as a regular file because `apm compile -g` refuses a symlink, and runs APM with the same secret unsetting. `agents/` is copied from the flake's store path into a writable `~/.apm/packages/dotfiles-agents`, which the manifest points to there (template variable `apmAgentsPath`), because APM fails on a read-only local package (`open() missing required argument 'flags'`, 0.35 and 0.39.1 alike; reported as [microsoft/apm#5544](https://github.com/microsoft/apm/issues/5544), the copy goes once it is fixed). The step reruns only when the hash from `apm-sync.json` changes, and records the hash only on success. A failure warns instead of failing `home-manager switch`, and the next switch retries.
