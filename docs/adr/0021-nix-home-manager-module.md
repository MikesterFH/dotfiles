# 0021: A home-manager module installs these dotfiles on NixOS

**Context:** The homelab is a NixOS fleet managed declaratively. chezmoi's install path (mise tools, apt, `run_` scripts that download binaries) does not fit there: nothing outside the Nix store should be mutable state, and a mise-installed binary needs `nix-ld`. Re-implementing the configs in Nix would fork them, and the two copies would drift.

**Decision:** The repo is also a flake with no inputs, exporting `homeManagerModules.default` (`flake.nix`, `nix/home-module.nix`; both sit outside `home/`, so chezmoi never deploys them). The module installs the CLI-tool Applications of a Profile from nixpkgs and wires the configs from `home/`: static files are linked straight from the store path, templates are rendered at build time by `chezmoi execute-template` with the data `chezmoi init` would generate (Profile, git identities). chezmoi itself never runs on the host and its `run_` scripts and externals are not used. Options live under `dotfiles.*` (`enable`, `profile`, `git.work`, `git.personal`). Only `personal` and `dev-server` are supported; `dev` needs a client identity the module does not model yet.

**Consequences:** The package list in `nix/home-module.nix` is a second copy of `$cliTools` and the mise runtimes: adding an Application means updating it too (noted in `AGENTS.md`). Node follows mise's `lts` by taking the highest even-numbered `nodejs_NN` in the consumer's nixpkgs (it has no LTS marker), so between an even major's April release and its October LTS promotion it can pick a release that is not LTS yet; `dotfiles.nodejs` overrides it. The yazi plugins from `package.toml` (`git`, `piper`) come from the `yazi-plugins` flake input instead of `ya pkg install`; its rev must match `package.toml`. Those plugins need a newer yazi than a stable nixpkgs ships (git.yazi wanted 26.8.15, nixos-26.05 had 26.5.6), so yazi alone comes from the `nixpkgs-unstable` input; drop that once stable catches up. `hunk` is not in nixpkgs, so the flake takes it from its own flake (`github:modem-dev/hunk`, input `hunk`, built with that flake's own nixpkgs); it only exists for the systems hunk's flake supports, and it floats until `nix flake update hunk`. Neovim and tree-sitter come from the consumer's nixpkgs, not the ADR 0013 pins, so `lazy-lock.json` can be one patch release off. `~/.config/nvim` is a read-only store link, so `:Lazy update` cannot write the lockfile there. The `dot_bashrc` calls to `brew shellenv` and `export-esp.sh` are guarded, since neither exists on NixOS.
